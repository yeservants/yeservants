3 · How the Site Is Built

A few deliberate architectural decisions keep the site fast, bilingual, and easy to extend without breaking.

Astro Islands

Pages are written in Astro and act as the data layer — they load content and optimize images. Every interactive piece is a self-contained React "island" that only loads its JavaScript when it scrolls into view. Result: the page is readable instantly; interactivity hydrates lazily.

Bilingual system (EN / ES)

All copy lives in a translation registry. Each page owns its own translation file (home.ts, about.ts, ourWork.ts, etc.) so English and Spanish always stay in sync and never collide. A language toggle remembers the visitor's choice and switches the whole site live — no page reload.

Every key has a matching English and Spanish value. The V3 guide's exact English copy is preserved verbatim; Spanish is a faithful, dignified translation.

Scroll-reveal & motion

Sections reveal with a gentle "mask-up" as you scroll — reverent, never flashy, matching the V3 tone ("let impact lines sit in silence"). Smooth scrolling is powered by Lenis; the hero headline reveals line-by-line via GSAP. Visitors who prefer reduced motion see everything immediately, fully accessible.

Brand system

The V3 brand is encoded once as design tokens and reused everywhere:

Forest green #2D5233 Orange #E8751A Off-white #F0EDE6 Playfair Display (headings) Lora (body)

Accent orange is tiered for accessibility: bright #E8751A for large display only; a deeper #A84F0A for small text, links, and buttons so all text meets WCAG AA contrast.

6 · Fidelity to the Guide

How we guaranteed the site says what the client wrote — and carries the tone the guide asks for.

Copy is verbatim

Every headline, impact line, anecdote, and Scripture reference from the V3 PDF is reproduced exactly. The thematic line — "If we are one Body, no servant of Christ should stand alone" — is used with weight, only on the Hero and the Biblical Foundation, exactly as the guide instructs.

Structure is one-to-one

Page order, section order, and section count all match the guide. Nothing was reordered, merged, or invented. Where the guide named 9 homepage sections, there are 9 components.

Tone is "Reverent Editorial Authority"

The guide asks for dignity, whitespace, and a premium faith-magazine gravity. Delivered through the Playfair/Lora serif pairing, deep-green dominance with restrained orange, real field photography (never stock or poverty spectacle), and quiet motion that lets impact lines breathe.

Theology preserved

John 17:21 · John 13:35 · Romans 10:14–15 are placed where the guide places them, in the Biblical Foundation and supporting sections.

Awaiting client content

A handful of items in the guide require the client's real data. These are marked in-code (<!-- CLIENT: … -->) and listed in CLIENT-CHECKLIST.md: exact statistics (number of nations / workers / teams), EIN, leadership bios & headshots, worker quotes, financial/annual-report links, and authentic field photos (Bajo Rodríguez CR · Mata Hambre HN · Ozamiz PH · Yanomàmö VE). Everything else is complete and live.

7 · Deployment & Maintenance

The site maintains itself. There is no server, no database, and no hosting bill.

  • Automatic deploy. Pushing code to GitHub triggers a build (GitHub Actions) that compiles the site and publishes it to GitHub Pages — typically live within a minute.
  • Static & free. The output is plain files served by a global CDN. Fast everywhere, nothing to patch or pay for.
  • Version-controlled. Every change is tracked in Git; any version can be restored.
  • Easy content edits. Adding a Gospel Worker = adding one Markdown file. Updating copy = editing the page's translation file (both languages side by side).
  • SEO-ready. Auto-generated sitemap, per-page titles/descriptions, and NonprofitOrganization structured data help search engines and AI assistants find and cite YES.
